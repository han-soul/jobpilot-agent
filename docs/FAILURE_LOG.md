# Failure Log

记录真实遇到并修复的问题，用于项目复盘和面试讲解。

## 1. API Key 被错误写成变量名

- 现象：`dotenv_values().keys()` 返回的是密钥本身。
- 原因：`.env` 只写了值，没有写 `DEEPSEEK_API_KEY=`。
- 修复：改成 `变量名=变量值` 格式。
- 教训：配置错误和业务代码错误要分层定位。

## 2. 缺少 tzdata

- 现象：`ZoneInfoNotFoundError: No time zone found with key Asia/Shanghai`。
- 原因：Windows/Anaconda 环境没有完整 IANA 时区数据。
- 修复：在当前虚拟环境安装 `tzdata`。
- 教训：工具内部异常需要先看 Traceback 最后一行。

## 3. Markdown 内容被转义

- 现象：检索把整份简历作为单个 Chunk 返回。
- 原因：文档中的 `#` 和 `-` 前面存在反斜杠，标题切分规则失效。
- 修复：清洗文档后重新建立检索索引。
- 教训：RAG 效果差可能来自数据清洗或分块，而不是模型能力。

## 4. 标题被过度切分

- 现象：检索只返回 `## 项目经历`，没有项目内容。
- 原因：分块正则同时匹配 `##` 和 `###`。
- 修复：只在二级标题处切分，保留子标题内容。
- 教训：Chunk 的边界要按业务语义设计。

## 5. 候选人技能只命中一项

- 现象：关键词覆盖率只有 5%，但模型在正文中认可了多项技能。
- 原因：候选人技能由模型临时填写，实际只传入了 Python。
- 修复：将可信技能放入 `skills.json`，由工具直接读取。
- 教训：确定性数据不应交给模型自由生成。

## 6. 主 Agent 结构化输出卡住

- 现象：工具调用完成后没有返回 `structured_response`。
- 原因：主 Agent 同时管理工具循环、复杂 Schema 和结构化输出，兼容性不稳定。
- 修复：改为两阶段流程，第一阶段分析，第二阶段只做结构化转换。
- 教训：职责分离能显著提高 Agent 系统稳定性。

## 7. 项目元数据未被召回

- 现象：报告错误地说简历没有项目时间。
- 原因：时间 Bullet 未被 Top-K 检索返回。
- 修复：在检索 Chunk 中附加项目时间、角色等元数据。
- 教训：RAG 不仅检索文本，还应携带来源和结构化元数据。
